# Infrastructure Monitoring and Alerting System

## Overview

This project implements an infrastructure monitoring and alerting system using Prometheus, Alertmanager, Grafana, and Node Exporter. It collects server metrics, monitors system availability, visualizes performance data, and sends alerts through Telegram when issues are detected.

The system is containerized using Docker Compose, making it easier to deploy and manage its components.

## Architecture

- **Prometheus:** Collects and stores metrics from configured monitoring targets.
- **Node Exporter:** Exposes Linux server metrics, including CPU, memory, disk, and system information.
- **Alertmanager:** Manages and routes alerts generated by Prometheus.
- **Grafana:** Provides dashboards for visualizing metrics and monitoring server performance.
- **Telegram:** Receives alert notifications through a Telegram bot.
- **Docker Compose:** Runs and manages the monitoring stack.

## How It Works

1. Node Exporter exposes system metrics from the monitored Linux servers.
2. Prometheus periodically scrapes metrics from the configured targets.
3. Prometheus evaluates alerting rules to detect conditions such as unavailable servers.
4. Alertmanager receives firing alerts and routes notifications to Telegram.
5. Grafana connects to Prometheus as a data source and displays monitoring dashboards.

## Configuration

### Prometheus

The Prometheus configuration defines the scrape interval, monitoring targets, and alerting rules.

Example:

```yaml
global:
  scrape_interval: 15s

rule_files:
  - /etc/prometheus/alerting.rules.yaml

scrape_configs:
  - job_name: "linux servers"
    static_configs:
      - targets:
          - "SERVER_IP:9100"
```

Replace `SERVER_IP:9100` with the address of a monitored server running Node Exporter. Configure additional targets as needed.

### Alerting Rules

Example rule for detecting unavailable targets:

```yaml
groups:
  - name: server-alerts
    rules:
      - alert: Server_Availability
        expr: up{job="linux servers"} == 0
        for: 10s
        labels:
          severity: high
        annotations:
          summary: "Server is unavailable"
          description: "Prometheus cannot scrape the target."
```

### Alertmanager and Telegram

Alertmanager handles alerts and sends notifications to a Telegram chat using a configured Telegram bot.

**Security note:** Keep Telegram bot tokens and other credentials out of source control. Use protected secret files or environment-based configuration, and add sensitive files to `.gitignore`.

## Deployment

### Prerequisites

- Docker installed
- Docker Compose installed
- Linux server(s) with Node Exporter running
- Network connectivity between Prometheus and the monitoring targets

### Run the Stack

Clone the repository:

```bash
git clone <YOUR_REPOSITORY_URL>
cd <YOUR_REPOSITORY_DIRECTORY>
```

Start the services:

```bash
docker compose up -d
```

Check the running containers:

```bash
docker compose ps
```

View service logs:

```bash
docker compose logs -f
```

## Access the Services

Once the containers are running, access the services using the appropriate host address and configured ports.

| Service | Default Port |
|---|---:|
| Prometheus | 9090 |
| Alertmanager | 9093 |
| Grafana | 3000 |
| Node Exporter | 9100 |

For example, if the stack runs locally:

- Prometheus: `http://localhost:9090`
- Alertmanager: `http://localhost:9093`
- Grafana: `http://localhost:3000`

Grafana credentials depend on your configuration.

## Security Considerations

- Never commit Telegram bot tokens or passwords to GitHub.
- Use `.gitignore` for sensitive configuration files.
- Avoid exposing monitoring interfaces directly to the public internet.
- Restrict access using firewall rules, authentication, and secure network configurations.
- Use HTTPS and appropriate access controls for production deployments.
